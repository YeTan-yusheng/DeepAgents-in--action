## 异步子Agent
**特点**： 不阻塞主对话，可以中途取消或追加指令，同时子Agent有自己的会话，会话历史持续累积

**协议、运行服务与追踪**

| 名称 |  本章中的职责  |
| ---	| --- |
| Agent Protocol | 一套调用 Agent 的 API 规范，约定如何创建会话、启动运行、查询状态和取消任务等 |
| Agent Server | 实现这些接口的运行服务，加载 Agent 代码，调度执行并管理会话状态与结果 |
| LangSmith Deployment | 部署和运行 Agent Server 的平台能力；也可以使用自托管的兼容服务 |
| LangSmith Observability | 采集和查看 trace，帮助分析模型调用、工具执行、耗时与错误 |

> 通过声明AsyncSubAgent(...)来创建异步子Agent。
> 其中 name 是异步子Agent的唯一标识，用于主Agent启动任务时指定；
> description 是异步子Agent的描述，主Agent据此理解子Agent的功能和限制；
> graph_id 是 Agent Protocol 服务上的 graph / assistant ID；LangGraph 部署需在 langgraph.json 中注册；
> 非必填字段 url 和 header 用于指定自定义的 Agent Protocol 服务地址和请求头。


## 主Agent的工具
| 工具 | 作用        | 返回     |
| ---|-----|--------|
| start_async_task | 启动一个新的后台任务 | 任务 ID（立即返回） |
| check_async_task | 查询任务当前状态与结果 | 状态 + 结果（若完成） |
| update_async_task | 给运行中的任务追加新指令 | 确认 + 更新后状态 |
| cancel_async_task | 终止运行中的任务 | 确认信息   |
| list_async_tasks | 列出所有任务（含实时状态） | 任务总览   |

## async_tasks 通道
> **作用**：独立于消息历史，存放每个任务的：task ID、子Agent名、thread ID、run ID、状态、
> created_at、last_checked_at、last_updated_at。
> 
> **目的**： 防止信息在工具消息里主Agent上下文过长压缩导致子任务丢失，所以独立存放于另一个channel中。

## 什么时候用 HTTP？
- 子智能体需要独立扩缩容
- 子智能体要不一样的资源画像（GPU / 大内存）
- 子智能体由另一个团队维护、独立发布

# 第七章

## Skills
> skill 是一个目录，里面可以包含业务逻辑，格式规范等内容，
> 方便Agent更好的协助我们完成任务。


### skills结构：
- skills/
    - SKILL.md    #元数据和核心指令
    - scripts/    #可执行脚本
    - references/ #详细参考文档
    - assets/     #模板、数据文件、schema 等静态资源

### SKILL.md的结构
- YAML frontmatter 元数据
  > Frontmatter 定义了 Skill 的身份和约束条件。
  >
  > 必填字段： name， **description**(最重要的字段，Agent选择Skill的唯一依据)
- Markdown 指令正文
  >  Agent 被激活该 Skill 后实际执行的”剧本”。


## Progressive Disclosure 渐进式加载
> 渐进式加载是指在加载 Skill 时，根据需要动态加载不同的部分,
> 而不是一次性加载所有内容。
> 这可以提高加载效率，减少内存占用，同时也可以根据任务需求动态调整加载内容。

### 三层加载机制
- L1： name + description + 文件路径
- L2: SKILL.md 正文
- L3: scripts/、references/、assets/ 下的文件

## Skills使用方法
**三种存储后端**：
- FilesystemBackend
- StateBackend
- StoreBackend

## 子Agent的Skills
> 通用子 Agent 自动继承主Agent的 Skills，无需手动配置。
> 
> 自定义子Agent的Skills，需要在子Agent的配置中指定。
> 
> 每个子Agent用于独立的Skill空间，互不干扰。

## Skills 执行代码的两种模式
- 沙箱脚本：适合API调用、数据处理、文件交换；需要沙箱后端 
- 解释器技能： 适合确定性逻辑，可复用函数； 需要CodeInterpreterMiddleware

## Skills、Memory、Tools对比
Skills：按需加载的领域能力
Memory：启动时加载的持久上下文
Tools：Agent可调用的编程操作
**决策规则**
Skills：特定任务才需要的指令
Memory：所有对话都需要的
Tools： 需要执行的原子操作

## 编写高效Skills的最佳实践
1.Frontmatter保持精简
2.SKILL.md 正文控制在 5000 tokens / 500 行以内
3.为 Agent 而非人类写结构
4.管控 Skill 数量
