## 异步子Agent
**特点**： 不阻塞主对话，可以中途取消或追加指令，同时子Agent有自己的会话，会话历史持续累积

**协议、运行服务与追踪**

| 名称 |  本章中的职责  |
| ---	| --- |
| Agent Protocol | 一套调用 Agent 的 API 规范，约定如何创建会话、启动运行、查询状态和取消任务等 |
| Agent Server | 实现这些接口的运行服务，加载 Agent 代码，调度执行并管理会话状态与结果 |
| LangSmith Deployment | 部署和运行 Agent Server 的平台能力；也可以使用自托管的兼容服务 |
| LangSmith Observability | 采集和查看 trace，帮助分析模型调用、工具执行、耗时与错误 |

> 通过声明AsyncSubAgent(...)来创建异步子Agent。
> 其中 name 是异步子Agent的唯一标识，用于主Agent启动任务时指定；
> description 是异步子Agent的描述，主Agent据此理解子Agent的功能和限制；
> graph_id 是 Agent Protocol 服务上的 graph / assistant ID；LangGraph 部署需在 langgraph.json 中注册；
> 非必填字段 url 和 header 用于指定自定义的 Agent Protocol 服务地址和请求头。


## 主Agent的工具
| 工具 | 作用        | 返回     |
| ---|-----|--------|
| start_async_task | 启动一个新的后台任务 | 任务 ID（立即返回） |
| check_async_task | 查询任务当前状态与结果 | 状态 + 结果（若完成） |
| update_async_task | 给运行中的任务追加新指令 | 确认 + 更新后状态 |
| cancel_async_task | 终止运行中的任务 | 确认信息   |
| list_async_tasks | 列出所有任务（含实时状态） | 任务总览   |

## async_tasks 通道
> **作用**：独立于消息历史，存放每个任务的：task ID、子Agent名、thread ID、run ID、状态、
> created_at、last_checked_at、last_updated_at。
> 
> **目的**： 防止信息在工具消息里主Agent上下文过长压缩导致子任务丢失，所以独立存放于另一个channel中。

## 什么时候用 HTTP？
- 子智能体需要独立扩缩容
- 子智能体要不一样的资源画像（GPU / 大内存）
- 子智能体由另一个团队维护、独立发布
