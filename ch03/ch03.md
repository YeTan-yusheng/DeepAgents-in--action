# CH03

## 第三章

### 文件系统
> 背景：传统Agent把所有信息塞进prompt，导致prompt过长，影响Agent的性能。
> 
> Deep Agents 解决方案：引入文件系统，为Agent提供一整套文件操作工具，模仿人类按需要读取文件、写入文件、创建文件、删除文件等操作。

#### 内置文件系统工具
> ls, read_file, write_file, edit_file, delete, glob, grep

1. **read_file**: <br>
    - 支持分片读取:
       ```python
       # 默认最多读取前 100 行
       read_file("/workspace/report.md")
       
       # 从第 100 行开始，读取 50 行
       read_file("/workspace/report.md", offset=100, limit=50)
       ```
    - 原生多模态：支持图片、视频、音频、PDF/PPT 等格式。
2. **grep**: <br>
    - **支持三种输出模式**:
       - files_with_matches：只返回匹配的文件路径（快速定位）
       - content：返回匹配行及上下文（深入查看）
       - count：返回匹配数量（概览统计）

---

### 上下文自动管理机制
**大结果自动卸载**： 当工具调用输出超过限额（通过tool_token_limit_before_evict 配置）时，Deep Agents 会自动将完整内容写入虚拟文件系统，在对话历史中替换为文件路径和预览，需要时可以按需返回。
<br>
**对话历史总结**： 当上下文达到配置的阈值时，Deep Agents 会启动自动总结。将待总结的旧消息写入Backend，保存以供后续查阅，用LLM生产摘要并附上历史保存路径，将本次发送给模型的内容换成“摘要 + 近期消息”。

### 可插拔存储后端

#### 1. StateBackend（默认）：临时存储
   - 同一个对话线程内持久化（多轮对话不丢失）
   - 对话结束后丢失（换一个 thread 就没了）
   - 主 Agent 和子 Agent 共享文件
   > 示例代码可查看：01StateBackend.py
   > 
   >适合场景：大多数情况下的默认选择，Agent 的”草稿纸”。

#### 2.FilesystemBackend：本地磁盘存储
   - 持久化存储，文件在本地磁盘上
   - 文件修改是永久的、不可逆的
   > 示例代码可查看：02FilesystemBackend.py
   > 
   >适合场景：本地开发 CLI（编程助手）、CI/CD 流水线。

#### 3.LocalShellBackend：本地 Shell 执行
   - LocalShellBackend 是 FilesystemBackend 的扩展，在文件系统工具之外额外提供 execute 工具，可直接在宿主机运行 Shell 命令。
   - 命令通过 subprocess.run(shell=True) 执行，无任何沙箱隔离
   - 支持 timeout（默认 120 秒）、max_output_bytes（默认 100,000）、env 等参数
   - root_dir 作为命令的工作目录，但命令可访问系统上任意路径
   > 示例代码可查看：03LocalShellBackend.py
   > 
   >适合场景：本地开发环境的编程助手、你完全信任 Agent 行为的个人开发机。

#### 4.StoreBackend：跨会话持久化
   - 跨线程持久化——不同对话都能访问同一份文件
   - namespace 参数控制数据隔离：lambda rt: (rt.server_info.user.identity,) 按用户隔离，防止数据混用
   - 开发用 InMemoryStore，部署到 LangSmith 时省略 store 参数（平台自动配置）
   > 示例代码可查看：04StoreBackend.py
   > 
   > 适合场景：长期记忆、跨会话的用户偏好、累积的知识库。

#### 5.CompositeBackend：混合路由
   - 这是最灵活的方案——不同路径走不同后端
   > 示例代码可查看：05CompositeBackend.py
   > 
   > 这种设计让 Agent 既有快速的”草稿纸”（State），又有持久的”记忆库”（Store），通过路径前缀自然隔离。

### 自定义后端与安全策略
**声明式权限：FilesystemPermission**
>最简单的路径访问控制方式是使用 FilesystemPermission，无需修改后端代码

**实现自定义后端：**
> 如果内置后端不满足需求（比如要接入 S3 或 Postgres），可以实现 BackendProtocol 接口

**安全策略：PolicyWrapper**
> 对于需要拦截策略（速率限制、审计日志、内容检查）的场景，可以通过继承或包装后端实现：
> - 方式一：继承现有后端
> - 方式二：通用包装器（适用于任何后端）


### 总结
- **文件系统**：为Agent提供一整套文件操作工具，模仿人类按需要读取文件、写入文件、创建文件、删除文件等操作。
- **深入了解了自动上下文管理机制**：大结果自动卸载，对话历史总结
- **深入了解可插拔后端**：StateBackend（临时）、FilesystemBackend（本地磁盘）、LocalShellBackend（本地 Shell）、StoreBackend（持久化）、CompositeBackend（混合路由）、沙箱后端（安全执行）
- **初步了解权限控制**：FilesystemPermission 声明式权限；GuardedBackend 或 PolicyWrapper 实现定制策略
