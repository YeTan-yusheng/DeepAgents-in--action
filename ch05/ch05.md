# 第五章
## 为什么需要子Agent？
> 上下文膨胀问题，主Agent不需要知道某些工具调用的详细信息，只需要知道工具调用的结果即可。

> 子Agent负责执行工具调用，主Agent负责协调子Agent的工作。

## 子Agent的核心机制
**Context Quarantine（上下文隔离）**
> 主Agent通过task创建一个子Agent，子Agent在独立的上下文中完成任务，只把最终结果返回给主Agent
> 子Agent的上下文不会影响主Agent的上下文，也不会被主Agent的上下文所影响。
> 
> 类比：项目经理和子项目负责人

## 什么时候使用子Agent？
> 当主Agent需要执行一个复杂任务，这个任务需要多个子任务时，并且主任务只需要子任务的结果，主Agent可以创建一个子Agent来执行这些子任务。

## 定义子Agent的方式
> 字典方式
```python
subagent = {
    "name": "researcher", 
    "description": "...",
    "system_prompt": "..."
}
agent = create_deep_agent(
    model=model,         
    subagents=[subagent], 
)
```

## General-purpose 子Agent
Deep Agents 自带的子Agent
> **作用**： 上下文隔离
> 
> 继承主Agent的system_prompt、tools、model 和 skills，
> 主 Agent 显式启用 Todo 时，它也会继承同一个 Todo Middleware 配置。

**如何禁用 general-purpose 子 Agent**
```python
register_harness_profile(
    key="openai:zai-org/GLM-5.2",
    profile=HarnessProfile(
        general_purpose_subagent=GeneralPurposeSubagentProfile(
            enabled=False
        )
    ),
)

agent = create_deep_agent(
    model=model,
    subagents=[],  # 不传任何同步子 Agent
)
```
> 可以通过 "name": "general-purpose" 配置默认子Agent

> 大多数情况使用字典
> 子 Agent 需要复杂的多步骤工作流或已经有现成的 LangGraph 图，使用 CompiledSubAgent。

## 多子Agent协作模式
> 主Agent作为协调者，协调多个专业的子Agent的工作。

**如何配置多子Agent协作模式**
> 通过 response_format 字段，主Agent可以指定子Agent的输出格式，从而方便主Agent程序化处理。

## 子Agent的最佳实践
1. 描述要具体
2. System Prompt 要详细
3. 工具集要精简
4. 不同子Agent用不同模型
5. 返回结果要精简

- 通过本章学习了解了子Agent的核心机制、什么时候使用子Agent、定义子Agent的方式、General-purpose 子Agent、CompiledSubAgent、多子Agent协作模式、子Agent的最佳实践。
- 子Agent可以帮助我们解决上下文膨胀问题，提高模型的性能和效率。
