# 第四章

### 为什么Agent需要任务规划能力？
> 复杂任务Agent容易遗漏步骤或重复搜索，上下文太长导致Agent失去了对整体进度的把控，同时质量不稳定。

> 使用场景： 长程、多阶段、容易漏步骤的任务；UI需要展示计划、当前步骤和进度；能力较弱、容易失去主线的模型通常也值得尝试。

**write_todos**
> 启用后，让Agent可以创建和管理任务清单。具体行为有模型、提示词和任务复杂度共同决定。
>
> 底层实现： LangChain 的 TodoListMiddleware
**三种状态** ：
1. pending(待办，Agent刚规划出来，还没开始做)
2. in_progress(进行中，Agent正在执行这个步骤)
3. completed(已完成，Agent将任务标记为完成)

**Agent使用write_todos的典型行为**：制定计划、逐步执行、动态调整。

**任务清单的持久化**
> 任务清单保存在todos字段中，和消息历史分开管理。
> 同一次运行后续步骤可以继续访问，对话总结不会删除todos

### LangChain 中间件 
**LangChain提供的两类Hook**:

| 风格 | Hook | 执行方式|
|-----| ----- | -----|
|Node-style |  before_agent、before_model、after_model、after_agent | 编译成 Agent 图中的独立节点，按生命周期顺序运行 |
| Wrap-style | wrap_model_call、wrap_tool_call | 包裹一次模型或工具调用；可以不调用、调用一次或多次 handler | 

interrupt()的人工中断优先放在 Node-style Hook中

**默认中间件**：
>FilesystemMiddleware，SummarizationMiddleware，PatchToolCallsMiddleware，Prompt caching 等模型能力

**通过专有参数配置，由 Deep Agent 组装对应中间件**
> SubAgentMiddleware，SkillMiddleware，AsyncSubAgentMiddleware，MemoryMiddleware，HumanInTheLoopMiddleware

**通过middleware配置**
> TodoListMiddleware 等可选策略按需加入

### 面对不同问题的处理

| 遇到什么问题           | 谁来处理                            | 需要注意什么 |
|------------------|---------------------------------| ---------- |
| 历史里有工具调用，却缺少对应响应 | PatchToolCallsMiddleware 补充说明消息 |不重试工具，不验证结果是否正确| 
| 工具调用遇到可重试的异常     | 应用显式配置的 ToolRetryMiddleware     | 是否重试、重试次数由策略决定；写操作还要考虑重复执行 |
| 下一次运行继续上一次的状态    | Checkpointer 配合同一个 thread_id    | 跨进程恢复需要持久化 Checkpointer |
| 工具返回了内容，但内容是否正确  | 应用的校验、评测或人工审核                   | 调用成功、清单完成都不等于结果正确               |


### SummarizationMiddleware: 上下文压缩的真身
LangChain 也有一个同名中间件，Deep Agents 复用了它的摘要逻辑,但两者的执行位置和消息处理方式不同。

>LangChain: before_model / abefore_model，在图中形成独立节点;
> 将当前 state["messages"] 中的旧消息替换为摘要，保留近期消息;
> 不负责将旧消息写入 Backend
> 
>Deep Agents: wrap_model_call / awrap_model_call，在 model 节点内部执行;
> 保留原始消息，另外记录摘要和截断位置；本次模型输入使用“摘要 + 近期消息” ；
> 将待总结的旧消息写入 Backend，摘要中附上保存路径
